# CLAUDE.md

Настольное приложение на tkinter для инженера, работающего с Huawei: учёт Core/кластеров/TOR, генератор VLAN-конфигов, парсер правил Huawei USG. Описание для пользователя — в README.md, планы — в BACKLOG.md.

## Запуск

```bash
.venv\Scripts\python.exe gui.py
```

Зависимость одна: `openpyxl`. Новые зависимости не добавлять без явной просьбы: приложение собирается в exe через Nuitka, и каждый пакет усложняет сборку.

## Архитектура

- `gui.py`: `HuaweiConfigApp` (окно и боковая навигация) и страницы-наследники `Page`: `NetworkPage`, `VlanPage`, `GeneratorPage`, `UsgPage`. Страница перечитывает данные в `on_show()`. Статус выводится через `app.set_status()`, без всплывающих окон об успехе.
- `theme.py`: вся палитра и стили ttk (тема `clam`). Цвета и шрифты брать только отсюда, не хардкодить в страницах.
- `dialogs.py`: `FormDialog` — одна форма на все сущности, поля задаются описанием (`entry` / `combo` / `text`, `wide`, `hint`, `required`). Новые формы делать через неё.
- `db.py`: работа с SQLite через хелперы `_rows` / `_row` / `_insert` / `_update`. `PRAGMA foreign_keys = ON` включается в `get_connection()`, на нём держится каскадное удаление. Изменения схемы — только миграциями в `init_db()`.
- `config_generator.py`: `generate_configs_for_selection()` возвращает `{hostname: [команды]}`. Логика восстановлена из Nuitka-сборки, текст команд менять осознанно: его применяют на реальном оборудовании.
- `usg_parser.py`: однопроходный парсер, блоки определяются **по отступам** (строка с отступом 0 закрывает блок). Адреса хранятся как `ipaddress.IPv4Network`. `search()` возвращает строки-словари; колонки и их порядок задаёт `COLUMNS` (таблица в GUI и Excel строятся из него).

## Соглашения

- UI, комментарии и docstring — на русском.
- Код без лишних абстракций, стиль как в окружающих файлах.
- Реальные конфиги, базу и выгрузки не коммитить (см. `.gitignore`). В коде, примерах и тестах использовать обезличенные адреса (`10.0.0.0/8`, документационные `192.0.2.0/24`) и вымышленные имена.

## Проверка изменений

Автотестов пока нет (см. BACKLOG). После правок:
1. Импорт и компиляция: `python -c "import gui"`.
2. Парсер: прогнать `usg_parser.parse_config()` и `search()` на конфиге и сравнить число правил с `grep -c "^ rule name"`.
3. GUI: запустить и пройти все четыре страницы. Изменения внешнего вида проверять скриншотом, а не на глаз по коду. Тестировать на **копии** `switches.db`, подменив `db.DB_FILE`.

## Подводные камни tkinter

- `root.option_add("*Font", …)` перебивает шрифты из стилей ttk, поэтому шрифты задаются через именованные шрифты (`TkDefaultFont` и т.д.).
- В `clam` у readonly-комбобокса в фокусе текст по умолчанию белый. Это переопределено в `theme.apply()`.
- В `pack` побеждает тот, кто упакован раньше: кнопки панели пакуются до растягиваемого поля.
- `Toplevel` диалога — дочерний элемент страницы, а не `root`.
